# R-SCHED-PERMISSION-PREHINT — 定时任务创建时的权限预检与预授权提示（P4，简单设计，深入待后续）

**状态**：简单设计已记录，**未实现**。owner 决定"先简单设计一下记下来，以后再深入调研和设计以及开发"。属 ADR-034（预授权 grants）的体验延伸。

## 问题
定时任务里如果有外部动作（如发邮件给某地址），当前每次触发都会停下来等审批（除非已在 `/approvals` 里预授权该地址）。owner 实测反馈：Run Now 后过一会才出现审批红点、选 Always allow 才把地址加白名单——**期望在创建定时任务时就检测所需权限，直接问"是否加入预授权"**，省掉"跑一次→被拦→再去批"的往返。

## 首版倾向（轻量启发式，低成本先上）
- 建 `agent_task` 时，对 `prompt`（+ `delivery_channel`）做**纯文本启发式**扫描，识别"可能需要预授权的外部动作"。首个也是最常见的场景：**发邮件**——用邮箱正则从 prompt 里抽出收件地址。
- 前端在创建表单提交前/后弹一个确认："这个任务看起来会给 `x@y.com` 发邮件，是否加入可信收件人（免逐次审批）?" → 勾选则调 `POST /grants`（send_email 白名单，复用 ADR-034）。
- **纯提示、非强制**；不改审批安全模型（不勾就仍每次审批）。owner 专属，agent 不参与。

### 优点 / 局限
- 优点：零模型成本、即时、覆盖 80% 的"定时发邮件给自己"场景。
- 局限：启发式不精确（prompt 措辞多样、可能漏检或误检）；只覆盖 send_email；无法预知 agent 运行时实际会调哪些工具/参数。

## 后续深入方向（待调研/设计）
- **模型 dry-run 预分析**：建任务时跑一次"只分析不执行"的模型调用（类似 ADR-009 的 no-tool 抽取），让模型列出"这个任务会用哪些工具、对哪些目标"，据此精确提示预授权。成本/延迟需评估。
- **通用化**：不止 send_email——QQ 目标、（未来）代码执行范围等，复用 ADR-034 的 per-tool matcher + `derive_rule`，做成"工具→可预检参数"的登记表。
- **运行时学习**：首次被拦审批时，除了 Always allow，提供"以后此类任务都预授权 X"的更强选项（已部分由 `always` 覆盖）。
- **安全边界**：预检提示绝不自动加权限（必须 owner 显式勾选）；预检不得把 prompt/密钥发给第三方；grant 仍精确匹配不通配（ADR-034 不变量）。

## 依赖
复用 ADR-034 的 `permission_grants` + `POST /grants` + send_email matcher/deriver（`app/permissions/grants.py`）；无需新表。前端加在定时任务创建流程里。
